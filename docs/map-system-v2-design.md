# 地图系统 v2 设计文档

> 状态：讨论定稿（未实施）。本文是 2026-10 设计讨论的结论汇总，作为后续切片的基线。
> 与 `docs/map-system-design.md`（现行系统）的关系：本文是其演进方向，不替代现行实现；
> 切片落地前以现行文档与源码为准。
> 术语约定：slot = 离散层级序号；底板 = 种子生成的 MapGeometry 数据。

## 0. 一句话总纲

**层是序数不是高度，底板种子定、改了走入口、周期查表算、建造是实体、视线看遮挡、存档只记偏离出厂那几格、客户端渲染派生不判定。**

## 1. 世界模型：分层 2D（slot 模型）

世界由任意多层平面堆叠，每格带一个整数层号 level（Int8，有符号，负层留给地下）：

- **自然层**：种子生成、密铺。山就是多层台地——山脚 L0、山腰 L1、山顶 LN。
- **建造层**：玩家/模板建出的楼板、墙（L1+），稀疏存储，随实体入档。
- **负层**：地下预留路径；现有 cave/ruins 多图模式继续有效，两条路并存。

**层是纯序数，没有物理高度。** 服务端对 level 只做三件事：比大小（谁高）、判相邻（能不能跨）、判遮挡（挡不挡视线）。任何“米”的概念都不进入服务端数据与逻辑。

- 实体坐标 = (x, y, level)；移动在层内是纯 2D（现有逻辑零改动）。
- 跨层仅 ±1，且必须经连接器格（slope / stairs / elevator 语义）；楼梯实体声明它连接哪两层。
- cliff 语义格允许**高→低单向跳下**（借鉴光明旅者），禁止低→高；坠落伤害按层数配置。
- maxLevels 走配置（建议 16）。

## 2. 数据分层：四份，职责分明

| 层 | 内容 | 来源 | 存储 |
|---|---|---|---|
| 底板 | tiles 地面语义 + walkable 通行位 + level + 区域划分 | 种子生成 | 密铺数组；增量存档 |
| 建造层 | L1+ 楼板/墙/家具 | 玩家/模板 | 稀疏；随实体入档 |
| 派生视图 | 雪地/湿地面/室内语义 | 查询期现算 | 不落盘 |
| 实体 | 树/石/建筑/NPC | ECS | 现有实体快照通道 |

- 地理与实体生命周期分离的原设计意图保留：树石建筑是实体，砍烧拆不动地形数组。
- GridOccupancy 键从 (x,y) 升级为 (x,y,level)，同格多层共存（一楼床、二楼柜）。
- 区域结构（regionOfTile / regions）保持**只读**：区域是生态规则的坐标系，运行时改它牵连太大（v1 不做区域级变化）。

## 3. 地形可变性：写回入口 + 增量存档

### 3.1 背景

旧约定“MapGeometry 不可变”的原始动机（见 tmp/session-ses_fbf1.md 考古）是**生命周期分离**——地理一次算好、实体随时生死，消灭“读档重复刷怪”补丁。其三大顺带红利中，“种子重算免存档”已被 S5 全量快照弃用，“碰撞缓存按 mapId”“version 指纹缓存”两条在受控写回下可维护。运行期改地形当年从未被讨论，是被默认排除而非权衡后拒绝。

### 3.2 写回入口（机制，零存储）

改底板的唯一合法通道：`setGround / setWalkable / setLevel`（概念名）。内部负责：

1. 原地改数组；
2. 重算该图 version 指纹（fnv1a32 通道复用；level 字段必须进指纹 canonical 对象）；
3. 失效/重建该图碰撞缓存（低频事件，非热路径）；
4. 脏格 diff 推送在线客户端（推完即清）。

约束：只许 tick 系统调用、用确定性 RNG（离线补差可重放）。任何代码绕过入口直接写数组视为架构违规。

### 3.3 增量存档

- 落盘时对“种子重算的出厂底板”做 diff，存稀疏修改项 `{tileIndex, 字段, 终态值}`；存终态不存事件流（last-write-wins）。
- 修改数超阈值（约 10% tiles）降级为全量快照，运行时逻辑不变，仅序列化格式二选一。
- 存档记录底板 version；读档 = 种子重算 → 指纹比对（不一致**拒绝读档**，配置漂移显式报错，符合“旧档直接废弃”立场）→ 叠加修改项。
- WorldRecord.maps 从恒存在变为有修改才存在。

### 3.4 决策：什么走写回

| 变化 | 手段 | 理由 |
|---|---|---|
| 焦土、小径、淹没、塌方 | 写回 | 持久历史，种子重算不出来 |
| 结冰、解冻 | 写回（改 walkable） | 通行性变化，查表表达不了 |
| 冬雪、湿地面、季节色 | 派生函数 | 会自己变回去，写回会在存档里固化错误终态 |
| 树被砍、建筑被拆 | 实体（现状） | 本来就不是地形 |

建造系统默认不碰地形（实体占位）；唯一例外“永久地理改造”（填水造陆、真石板路）走写回入口，且**后置**——先用实体版顶，等玩法真出现再升级。

## 4. 季节与天气

- **WorldClock 相位系统**（框架新件）：tick → season/weather/temperature 相位机，全局标量状态；spawnConditions 注册表扩展 inPhase / isRaining。
- 效果三路落地：数值效果（体温/生长速率，查询期算）、实体效果（FSM + condition 门控）、视觉效果（客户端渲染）。
- **派生视图是纯函数**：`effectiveGround = f(底板语义, 相位, 相位进度, level, 区域, 格子hash)`。
  - 雪线按海拔：level ≥ snowline(相位进度) → 雪地，山顶先白、春天从低往高化；
  - 斑驳覆盖：hash(x, y, phase) < 覆盖率(进度)，不闪、每年同一批格子最后化；
  - 区域/背阴、被实体占用的格子不积雪；
  - 玩法与渲染调同一函数，天然一致；相位切换时重算缓存数组（192²≈3.7 万格，廉价）。
- 离线语义（待定，建议）：资源再生跑、袭击不跑、族群增长跑。定稿时写入 WorldClock 设计。

## 5. 视野与遮挡

**规则：遮挡物挡视线，不是层号挡视线。** 墙挡同层、楼板挡跨层、露天不挡。

- 判定必须**对称**（A 见 B ⟺ B 见 A），否则出“我能打我看不到的”exploit。实现用 voxel DDA（Amanatides-Woo）在 (x,y,level) 体素上；“跨越 (x,y) 列 L/L+1 被挡 ⟺ (x,y) 在 L+1 有楼板”，双向同判。
- gameplay LOS 与网络兴趣裁剪**分离**：LOS 管战斗/AI；兴趣裁剪（带宽与反 wallhack）v1 = 同层全给 + 露天跨层限半径。共用底层查询，策略独立。
- 玩法红利：封闭房屋 = 藏匿；登顶 = 跨层视野但暴露自己。
- 房间检测（墙围合 + 头顶有板）产出“室内”语义进派生层：室内不积雪、不淋雨、壁炉升温。小房间内部也可走星露谷路线（切独立小图），两条路并存。

## 6. 生态

行业结论（调研自 DS/Valheim/PZ/Green Hell 等）：**没有主流生存游戏跑真食物链**，生态感来自“可穷尽 + 有反馈”。

- **族群节点模型**：巢穴/兽群/聚落为节点，持 `{species, count, cap, growthRate, homeRegion}`；服务端演进数值，进入玩家视野才实例化为实体（复用演化引擎 exact/density 模式与离线补差）。捣毁巢穴 = 永久清除该种群来源。
- 捕食用事件规则近似（不做能量流）；季节迁移走 condition。
- 演化引擎“只增不删”不变式扩展为可插拔种群模式：density 刷新（现状）/ 族群节点 / 巢穴驱动并存，规则配置选择。
- 物种替换（去魔幻）：tentacle→鳄鱼；新增山羊（兽群迁徙）、海鸟、鱼群、蛇。ruins 去魔幻化为沉船/失事营地/考古遗迹。

## 7. 生成管线升级

```
noise-terrain(岛形遮罩+ridged)
  → quantize-terrain ★新（连续高度→离散 level + slope/cliff 派生 + walkable 修正；连续高度用完即弃）
  → whittaker-regions ★新（温度×湿度双通道分区）
  → river ★新（消费量化前连续梯度；湖泊=高度阈值）
  → ca-cave ★新（cellular automata + union-find 连通）
  → 现有积木（climate-regions/room-corridor/slot-rooms/stamp-template/…）
  → 放置层升级蓝噪声/Poisson（替代 32 次均匀尝试）
```

- quantize-terrain 配置：分带阈值、maxLevels、slope/cliff 语义 id。是 bandLevel/groundPalette 分带逻辑的自然演进。
- validate 升级为**可配置契约**：任意两可达台地间必有 slope 链；关键资源可达性；不再是 0.9 告警了事。
- 侵蚀/WFC/Voronoi 不进实时管线（过重/需裁剪）。
- 种子纪律：分层子种子 + generatorVersion + 指纹 golden test；收口现存 4 处 Math.random（deathSystem/inventoryOps/wander/spawn）。

## 8. 客户端与渲染契约

**元规则：服务端是共享状态唯一写入者；客户端一切几何判定均为 advisory（可纠正、可拒绝）。**（单机 HD-2D 游戏客户端即模拟器所以用 3D 碰撞——HeadlessHost 模式下模拟器跑的也是框架 2D ECS，结论不变。）

- 渲染换算：`世界高度 = level × storyHeight`，storyHeight 是**全局唯一常量**，任何 tile 类型不得有第二个值——“逻辑同层 = 视觉同层”的唯一保证。违反即渲染 bug。
- 合法自由度：层内微起伏（边界顶点钉在本层高度）、崖壁立面装饰（层间立面随便画多深）、远景 vista（不可达区域任意真实比例）。
- 楼层标签显示相对层号（level − 地面level + 1 = “2F”），内部编号玩家不可见。
- 3D 碰撞/射线仅允许：点击拾取（射线→(x,y,level) **多候选** + 层级循环 UX；实体走 networkId 通道，level 由服务端实体状态给出；服务端对一切交互做 level 维度重校验）、纯表现辅助（相机遮挡/贴地/粒子）。
- 客户端预测：默认不做（20tps + RPG 节奏，纯插值可行）；做则复制服务端 2D 碰撞数据本地跑（check2d 是 JS 库，同代码复用零分歧）。预测是增量能力，不是高度系统前置依赖。
- 内容管线契约：3D mesh 必须从同源 level/walkable/建造实体数据派生 +“视觉洞=碰撞洞”资产校验。
- 参照案例：RuneScape（3D 客户端 + 整数 tile 服务端 + 0.6s tick）、Albion Online（Unity 客户端，服务端自研碰撞，客户端库镜像+预测）。三角战略已验证“离散层级 + HD-2D 渲染”。

## 9. 前置修正清单（高度系统动工前必修）

1. 实体 level 载体组件（类比 EntityMap 的 AoS 模式：无 archetype initializer、运行时写入）+ netSync + 入档；level 转移 = (位置, 地图数据) 纯函数 + **滞回**（防连接器边界振荡）。
2. “无楼板 = walkable 0”编码进每层位图；v1 高台边缘即墙、无坠落（knockback/分离不会把实体推入非法状态）。
3. 统一 `walkableAtLevel(x,y,level)` = 地形 OR 建造实体，全消费方（projectile/spawnPlacement/placement）强制走它。
4. 统一 gameplay 距离/可达性助手（同层欧氏 / 跨层策略 + LOS），替换 combat/perception/interaction/placeable/deconstruct/crafting/dialogue/inventory/projectile **9 处散装距离检查**——整个扩展最大的系统性陷阱。
5. 投射物 v1 锁单层（目标必须同层）；跨层交战只允许 hitscan/命令式交互。
6. 碰撞静态体矩形合并（行游程）；上层只建墙格 + 楼板岛周界体（O(周长) 而非 O(面积)），否则高层全图静态体几十万 box。
7. level 进 computeGeometryVersion canonical 对象与快照序列化（漏加则缓存/存档无声错配）。
8. 连接器完整语义：双向/有向、建造连接器拆除的 stranded 策略（拆楼梯困二层）、高墙多层占格表示（多条记录 or footprint+levelRange）。

## 11. 不做 / 后置

- 真 3D 体素世界（连续碰撞/3D 模拟）：独立 v2 项目范畴，不在本框架演进。
- 运行时改区域归属（v1 不做）。
- 区域局部层级、实体定义逻辑高度（已否决：前者接缝换算灾难，后者滑向连续 3D）。
- 动态自建复杂多层交互（先把楼层建造切片跑通）。
- chunk 化无限地图（维持固定尺寸全图常驻）。
- autotile 渲染（客户端职责，服务端最多输出掩码）。
- 侵蚀/WFC（§7，过重）。

## 12. 直白版解释（给未来的自己）

**地图数据长什么样**：每张地图是一张方格网，每格记地面类型、能不能走、属于哪个区域、在第几层。“层”是这次新加的整数：山脚 0、山腰 1、山顶 2；二楼就是比地面大 1 的一层。层没有“米”，服务器只比大小——同层能直接走，跨层必须走楼梯/坡道格，悬崖就是层差太大没坡道的地方，上不去但能跳下来。

**地和地上东西分开管**（老规矩）：树、石头、房子是实体不是地图数据，会被砍烧拆、进存档；地图只管地面。

**地形从不许改改成登记改**：火烧焦土、湖面结冰这类改动走统一入口，改时顺便更新版本号、重建碰撞、推送给在线玩家；不许别的代码偷偷改数组。

**存档只存改动**：地图能用种子重新生成，落盘时只记和原始地图不一样的格子；读档先种子生成再盖回改动。改了地图配置或种子，底图和存档对不上就拒绝读档，避免错位。

**季节不改数据，查的时候算**：冬天雪地不是改数据改的，是查询时根据“季节、进度、层数、坐标”算出来的。数据不动，春天自动恢复，雪线随季节移动，同一些格子每年最晚化雪。玩家地板盖住的地不积雪。

**山和楼同一把尺**：山按“爬几段”切成整数层，楼每层占一层。半山腰（3 层）的房，二楼在 4 层，和旁边 4 层的山坡齐平，二楼直接走上山。全地图“层数→显示高度”只有一个换算系数，山楼共用，接缝永远对齐。山要更高就多切几层。

**能不能看见看遮挡物**：墙挡同层，楼板挡上下层，露天不挡。山脚看得见山顶的人，看不见二楼屋里的人。进屋=隐身，登顶=看得远但暴露。

**怎么画不归服务器管**：客户端拿格子数据自己画 3D/HD-2D，崖壁随便画多深、远景雪山随便放。但客户端不能用 3D 模型判定玩法，只能用射线算出玩家点的是哪格哪层发给服务器。

**生态不模拟食物链**：用族群节点记账——狼窝羊群是数量节点，玩家靠近才生成实体；打掉窝就不再刷。

**施工顺序**：季节时钟/随机数/事件接线 → 资源再生 → 族群生态 → 层数（数据+移动+碰撞）→ 多层建造+室内 → 地形写回+增量存档 → 新生成零件。动工前先修 8 个已知坑，最大的是 9 个系统各自算距离，加层后会全部悄悄出错，必须先统一成一个距离函数。
